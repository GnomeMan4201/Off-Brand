# Maintaining Off-Brand

## Configuration

- Configure GitHub Pages to use GitHub Actions.
- Set the optional `URLSCAN_API_KEY` repository secret for authenticated public scan collection.
- Optionally set `PHISHTANK_APP_KEY` if you hold a PhishTank application key. PhishTank has not issued new keys since 2020; without one the public dump is used, which allows only a few downloads per day.
- Configure `OFFBRAND_PROVENANCE_KEY` as a repository Actions secret containing 32 cryptographically random bytes encoded as 64 hex characters (for example generate locally with `openssl rand -hex 32`). Do not commit, paste into an issue, or share this key. Both collection and publication use it. Rotation invalidates all older pending attestations; existing published reviews are unaffected.
- Leave `URLSCAN_PUBLIC_REUSE_AUTHORIZED` unset until authorization for the intended reuse is documented; see [SOURCES.md](SOURCES.md).
- Ensure the `triage` and `approved` issue labels exist. The ingestion and publication workflows require the permissions declared in their workflow files.

## Review and publication

Manual ingestion (`ingest.yml`) searches up to 25 candidates per source and stages at most three fresh candidates per run. If urlscan yields no fresh candidates, public intake stages nothing. OpenPhish is private research only. Source labels are leads rather than verified verdicts.

## Evidence sources

| Source | Role | Notes |
|---|---|---|
| urlscan.io | Discovery, screenshots, scan records | Free search fields only |
| PhishTank | Verification of exact pages (hourly dump, looked up locally) | Unkeyed downloads: a few per day |
| OpenPhish community feed | Private cross-check only | Never shown publicly (terms) |

Limits and licensing for each source are in [SOURCES.md](SOURCES.md). Two manual, read-only workflows support this:

- **Source Health Check** (`source-health.yml`) reports each source's HTTP status, format, record count, freshness, rate limiting and last successful retrieval. Untick PhishTank to save its daily downloads.
- **Audit Published Evidence** (`audit-reviews.yml`) assesses every published review with the current rules and attaches a report to the run. It never edits `reviews.json`.

Every triage issue (public or shelf draft) includes an evidence section and an `evidence_json:` line generated by `scripts/evidence.py`. The publisher re-validates that block, recomputes the level from its records (so an edited level is rejected), strips sources that may not be republished, and refuses anything below Suspected. Unverified and Disputed specimens cannot be published, and nothing in the review comment changes the level. Every new issue body also carries an HMAC-SHA256 collection attestation bound to the repository, actual issue number and complete generated body. Only the owner-triggered main-branch workflows issue attestations. Do not edit generated issue bodies; write reviews in comments. Missing keys, unsigned legacy issues, edited bodies and copied attestations fail closed. A legacy issue must be rebuilt from independently recollected source material, not simply signed as-is. Legacy drafts are never migrated in place. To replace a mapped private shelf draft, run **Write This Specimen** with the specimen ID and the old issue number in `replace_legacy`; leave dry run enabled first. This requires the provenance secret and readable archived urlscan result (usually `URLSCAN_API_KEY`). It verifies the returned scan ID, public visibility, URL, capture timestamp and the saved screenshot hash, rejects disputed historical evidence, then creates a fresh authenticated private issue and updates the private shelf mapping. No old body, approval label or review comment is copied. The replacement reassesses only the provider record (no extra PhishTank download), so it may be Suspected or Unverified. Re-review it and approve the new issue separately. An old public triage issue can be recovered only after its specimen is collected into the private shelf and a fresh draft is generated; do not sign the old public issue. A partial failure that already created a valid replacement is recovered by reusing the authenticated draft on retry. If issue creation succeeds but the attestation edit fails, the unsigned issue cannot publish; resolve it manually before retrying collection. A valid signature authenticates the collector snapshot, not the external provider's claims or their current accuracy. The trusted boundary includes the owner, protected main branch, Actions secrets and private shelf contents. Feed downloads happen once per run; nothing contacts the suspect site. If a feed fails, the issue says which one and why.

Inspect the record and screenshot before approving a review. Use the key/value fields supplied in the triage issue:

```
brand: <Target brand>
aisle: <Category>
knockoff_label: <Satirical product name>
verdict: <Satirical verdict>
rating: <Rating out of 10>
sketchy_segment: <Exact defanged URL segment>
tells: <Observation> | <Observation>
critic_note: <Review>
voice: critic
edge: 2
```

The [editorial guide](../VOICE.md) and [voice roster](../data/voices.json) define the available voices and edge levels. The `approved` label alone never publishes. Use the comment menu to copy the review link, then run **Publish Approved Review** on main with the issue number and the numeric ID after `#issuecomment-`. Only the repository owner can dispatch publication, and the selected comment must be authored by that owner on the same open, labeled triage issue. Keep each field on one line; malformed or duplicate fields are rejected. Records that do not meet the editorial standard should not be approved; the published exclusion log is stored in `data/reviews.json` under `rejected_log`.

## Private specimen archive

Create a separate private repository with a default `main` branch and the `triage` and `approved` labels. Configure `SHELF_REPO` as the repository variable (owner/name) and `SHELF_TOKEN` as a secret restricted to that repository, with Contents and Issues read/write access. The archive workflows check that the shelf is private.

- `archive.yml`: collects existing urlscan records and screenshots. Manual runs default to dry-run; scheduled collection requires `ARCHIVE_SCHEDULE_ENABLED=true`. The default archive storage cap is 500 MB. Collection retains resume state.
- `write-specimen.yml`: creates or reuses a private draft issue for a selected specimen; optionally replaces a mapped legacy draft. Dry run defaults to true.
- `publish-shelf.yml`: publishes an approved private specimen using the same validation pipeline and an explicit review comment ID.
- The archive's Markdown index provides Unwritten, Drafted, Published and All views, with thumbnails and links to individual records. Screenshot observations are recorded in the private shelf's `data/archive_inspections.json` as attributed observations with image pointers.

The private archive, unapproved screenshots, draft notes and collection state must not be committed to the public repository. For privacy withdrawals, the public exclusion log retains the reason and a hashed specimen identifier rather than a domain or record link. Publication and intake reject excluded identifiers. Removing an asset from main does not erase older Git objects or external caches.

## Commercials

The manifest at `site/commercials/manifest.json` determines CH 00 listings and the rotation. Automatic breaks occur after 4–7 channel changes, start muted, respect reduced motion and can be disabled. A failed video returns the viewer to the program.

Store H.264/AAC MP4s and JPEG, PNG or WebP posters in `site/commercials/`, with lowercase alphanumeric/hyphen filenames. Keep videos below 25 MB. Use fast-start and remove unnecessary container metadata. Add a manifest entry with `id`, `title`, `runtime_seconds`, `src`, `poster` and `description`. Use `captions: "burned-in"` only for verified embedded captions, or provide a `captions_vtt` path for WebVTT. Set `enabled: false` to disable a commercial without deleting its assets.

## Local checks

```sh
mkdir -p _site/data
cp -r site/* _site/
cp data/reviews.json _site/data/
python3 -m http.server -d _site 8000
```

```sh
python3 -m pytest -q tests
```

Local checks may skip unavailable dependencies. Pull requests and deployments run the full suite with Node.js, ffprobe, Pillow, Playwright and Chrome; any skipped check blocks deployment. Review commercial frames and captions before adding media. Withdrawn material must not appear in commercials, posters or other public assets.
